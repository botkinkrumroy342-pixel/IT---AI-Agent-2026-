零基础手写 AI Agent：先理解原生最小内核
只会用现成 Agent 框架的人，往往能快速搭出演示，却说不清 Agent 到底如何运转。一旦出现死循环、工具误调、上下文溢出或成本失控，就无从下手。零基础手写 AI Agent 的第一课，不是学某个框架，而是理解原生最小内核：模型、状态、工具、循环和停止条件。把这五件事讲清楚，Agent 才不是黑盒。

原生 Agent 的本质是一个受控循环。它接收目标，把目标、历史对话、系统指令、工具说明和当前状态组织成上下文，交给大模型。模型返回的不是最终答案，而是下一步动作：可能是直接回答，可能是请求调用某个工具，也可能是要求澄清。系统解析这个动作，执行工具，把结果写回状态，再进入下一轮，直到任务完成、模型主动结束，或触发预算、步数、超时等停止条件。这个循环看似简单，却包含了 Agent 的全部关键矛盾：模型不确定、工具有副作用、状态会膨胀、目标可能模糊。

为什么建议手写最小内核？因为现成框架隐藏了太多细节。它们帮你封装了消息格式、工具协议、记忆检索、规划器和多 Agent 通信，但也让你失去对执行轨迹的控制。原生开发的优势是透明：每一次模型调用、每一次工具执行、每一次状态变更都能记录和审查。你可以决定上下文如何裁剪、工具权限如何限制、失败如何重试、危险操作何时转人工。对于零基础学习者，先手写一个单 Agent、单工具、单轮循环，比直接上多 Agent 框架更有价值。

最小内核需要几个核心抽象。第一是模型接口，统一不同供应商的调用方式，处理超时、重试、流式输出和用量统计。第二是消息与状态，区分系统指令、用户输入、助手回复、工具结果和内部笔记，并给它们不同优先级。第三是工具描述，包括名称、用途、参数结构、权限范围、超时时间和返回格式。第四是输出解析，把模型自然语言转成可执行动作，同时保留失败时的兜底策略。第五是执行器，负责调用工具、捕获异常、判断幂等和记录日志。第六是停止条件，包括最大步数、最大令牌、最大耗时、连续失败次数和人工中断。

零基础学习路径应循序渐进。先做纯对话循环，理解上下文累积。再加入一个只读工具，例如时间查询或文件读取，理解工具调用协议。然后加入写操作，但必须设置权限和确认。接着加入短期记忆摘要，避免上下文无限增长。再加入检索，让 Agent 能访问外部知识。最后才考虑任务规划和多 Agent。每一步都要有评测：任务是否完成、调用了几次模型、花了多少令牌、有没有无效工具调用、失败后能否恢复。没有评测，手写 Agent 只是换个方式抽卡。

原生开发还要重视安全边界。工具必须最小权限，敏感操作二次确认，密钥不进入上下文，输出要过滤，日志要审计。Agent 不应该拥有无限自由，而应在明确边界内行动。归根结底，手写 AI Agent 系统课的目标不是排斥框架，而是让你先掌握底层原理。能亲手实现最小内核，才能看懂框架源码，才能按需裁剪，才能在真实业务中排错和优化。只会调框架是使用工具，理解原生循环才是拥有能力。
